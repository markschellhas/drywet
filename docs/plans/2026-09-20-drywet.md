# drywet Implementation Plan

> Sequential plan. Implement task-by-task in order. Update each task **Status** as work advances. Progress counts only `done`.
> On resume: read **Progress** and each task **Status** / **Resume**. Do not redo completed tasks.

**Goal:** Ship a Rust crate `drywet` plus binary `drywet-engine`: one Transport, Tone-style time, Sampler / Synth / Drum, Sequence / Part / Loop, BufferSink + PipeWire callback sink, NDJSON stdio host.

**Architecture:** `Context` owns sample rate, channels, one sink, and one `Transport`. Instruments mix PCM onto that sink at sample frames. Sequence / Part / Loop only register callbacks that receive `time` and must pass it into triggers. Tests use `BufferSink` only. `drywet-engine` is a thin NDJSON adapter. Musician API matches drywet-py.

**PRD:** `docs/prds/prd-drywet.md`

**Heritage:** [drywet-py](https://github.com/markschellhas/drywet-py) feature maps and tests. Port behavior, not Python.

**Tech stack:** Rust edition 2021, `cargo test`. No audio crate required until Task 16. Engine uses only std for NDJSON in Task 17 (or `serde_json` if line parsing gets messy).

**Locked v1 decisions (from drywet-py + PRD):**

- `time_signature` is always `(n, d)` (int `4` → `(4, 4)`)
- Drum trigger names: `kick`, `snare`, `hat`
- BPM writes while running apply on the **next** `start`
- Default sample rate 44100, channels 1
- PPQ 192, BPM 40–240, MIDI 0–127, Hz 20–20000, max schedule 600 s
- Context defaults to `BufferSink` so tests never open PipeWire
- Language timers are not the clock

### [x] Task 4: BufferSink

**Status:** `done`
**Resume:** Complete
**Commits:** `48070735461c48732efb6deb95c24f31ae3141c3`
**Files:** `src/sink.rs`, `tests/buffer_sink.rs`

Port `BufferSink` from drywet-py.

- `mix(frames, at_sample)` adds into an expanding f32 buffer. Stereo duplicates a mono frame across channels.
- `write(frames)` mixes at `write_cursor` and advances it.
- Tails sum. `accepted` becomes true after first mix/write.
- `to_pcm_s16le` clips to [-1, 1] and packs little-endian i16.
- `stop` / `close` are no-ops. `latency_ms` is 0.

Define a `Sink` trait with `mix`, `write`, `stop`, `close`, `latency_ms`, `write_cursor`, `accepted` so Task 16 can add PipeWire behind the same trait.

**Tests:** `cargo test -q buffer_sink`
**Commit:** `feat(sink): BufferSink mix/write path for CI`
